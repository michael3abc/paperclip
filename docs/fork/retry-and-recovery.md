# retry-and-recovery

Moved verbatim from `FORK.md` on 2026-11-13. These rules and records stay binding; read this file before acting on the topic. Retry/recovery authority, creator/original-main notices, supersession rules

The same repair series distinguishes a scheduled disposition repair suppressed
before execution from unknown provider delivery. Its original scheduler event,
source/episode, skipped-or-cancelled wake and absent execution/resource evidence
must agree. Operator cancellation remains distinct; source history is retained.
Explicit registration also adopts historical remote project-primary rows in place
after owning-host Git evidence, without moving files or replaying their tasks.
Project-main continuation uses the original accepted Owner Chat and a current
run-authored handoff, with explicit task/run observations and a durable operation
receipt. The route and queue retain unknown-delivery, cancellation, policy,
supersession and human gates; no Board impersonation or empty-request bypass.

2026-11-12 queued authority rejection: distinguish a proven pre-dispatch input
rejection from uncertain provider delivery using the exact gate event, skipped
wake and all retained execution/resource fences. Admit a later independently
authorized saved input once through the existing coordinator, retaining the
rejected run/input, recovery rows and any separate unknown source incident.
Exact Bridge undispatched proof also separates remote instruction cleanup from
admission. Successful-source disposition repairs share the independent-input
fence and cannot coalesce with fresh comments in either direction.

2026-11-12 independent-input supersession: failed retries also lose automatic
authority when a genuine human or authorized project-main input is saved. Retry
scheduling, promotion and pre-dispatch share the issue admission fence, including
the comment/reopen-before-wake race and older retry ancestry; a failed child cannot erase an earlier Stop. Preserve original
failed runs, delivery uncertainty, interaction answers and worker results.

2026-11-12 cancelled retry authority: suppress automatic retry from cancelled
executions at scheduling, durable promotion and queued dispatch. Preserve only
matching pre-provider system resource-wait lanes; Stop wins over retained wait
proof. Fresh Owner comments retain separate authority from stale retry/rendered
continuation envelopes, including the locked coalescing check. Original failed
inputs and uncertain delivery remain unchanged; no production replay/backfill.

2026-11-12 adapter non-delivery provenance: preserve the adapter result fact and
original error before workspace finalization. New authorized Bridge input reads
that server-held receipt even when a later finalizer replaced the terminal error;
contradictory input/session/provider/process evidence still blocks admission.
Keep the original saved wake, failed run and cleanup obligations without replay.

2026-11-12 bounded original-main blocker repair: a failed notification turn and
its automatic retry lineage cannot alternate with generic continuation to obtain
fresh repair budgets. Preserve the original receipt, escalate failure after input
acceptance to Owner, and keep independent new Owner input eligible. Targeted
PostgreSQL tests cover the scheduler, retry writer and original notice lifecycle.

- Creator-notice deferred admission classification (2026-11-12): an exact durable
  `deferred_issue_execution` wake without a run retains its execution-wait reason
  instead of reporting unknown delivery. Event/restart reconciliation reads the
  same receipt without resending, repeated writes or premature preemption resume.
  Missing/mismatched receipt uncertainty and independent Owner input authority
  remain unchanged. Covered by isolated PostgreSQL and selected recovery-card tests.

- Original-main blocker delivery (2026-11-12): new recovery identities use durable
  original-conversation wakes, exact input receipts and event-driven reconciliation.
  Busy main waits for completion; recursive or uncertain delivery asks Owner once.
  Preserve permissions, holds, recovery budgets and historical actions. This is
  part of the staged shared-worktree feature, not a standalone rollout.

- Suppressed disposition repair settlement (2026-11-12): verify the full original
  server trace for a prepared repair rejected before provider dispatch. Retained
  instruction copies use normal collection/cleanup; the original workspace wait
  wakes once. Missing or contradictory proof remains blocked, including later
  provider events. No schema change, synthetic Stop or historical task replay.

- Workspace creator recovery (2026-11-11): structured pre-provider failure evidence, original-Chat
  system delivery with durable receipts, revision-bound single original-worker repair admission,
  explicit Owner historical forwarding and restricted terminal-holder reconciliation. No new tables,
  watchdog, force-unlock or provider replay. See `doc/DEVELOPING.md`, Workspace feature checks.
  Candidate acceptance also covers task-page visibility under system-attributed failure; the
  creator receipt mounts its card at the shared page level for new and classic Task Chat,
  suppressing the nested duplicate card and generic Retry banner.
